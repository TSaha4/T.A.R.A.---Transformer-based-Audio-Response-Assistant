# TARA Synthetic Chatbot Dataset

Fully synthetic dataset generated by template + slot-filling (no scraped or
copyrighted conversational data). Built to support **intent classification**,
**response generation**, **conversation history**, and **user memory/preference**
modeling for a voice-enabled deep-learning chatbot (TARA).

## Contents

| File | Description |
|---|---|
| `tara_dataset.jsonl` / `.json` | Full dataset, one record per line (JSONL) or as a JSON array |
| `tara_dataset.csv` | Full dataset in CSV form (`entities` column is a JSON string) |
| `tara_train.jsonl` / `.csv` | 80% stratified split (10,044 rows) |
| `tara_val.jsonl` / `.csv` | 10% stratified split (1,254 rows) |
| `tara_test.jsonl` / `.csv` | 10% stratified split (1,259 rows) |
| `label2id.json` | Intent → integer label mapping (19 classes), for training a classifier head |
| `dataset_stats.json` | Per-intent row counts |
| `conversation_history_sample.jsonl` | Example multi-turn session logs (see below) |
| `user_memory_sample.json` | Example user profile/preference store (see below) |
| `generate.py` | The generator script itself — rerun it (different seed) to regenerate or extend the dataset |

## Schema (per row)

```json
{
  "id": "tara_000123",
  "intent": "REMINDER",
  "utterance": "remind me to submit the assignment at 6 pm",
  "response": "Got it! I'll remind you to submit the assignment at 6 pm.",
  "entities": {"task": "submit the assignment", "time": "6 pm"}
}
```

- `intent`: one of the 19 classes below.
- `utterance`: the (synthetic) user input.
- `response`: a suitable assistant reply for that utterance — use this as
  ground truth for a response-generation / retrieval head, or as the
  canned reply your dialogue manager returns once intent is classified.
- `entities`: slot values extracted for that utterance (empty `{}` when an
  intent carries no slots, e.g. `GREETING`). Present for `WEATHER` (city,
  date), `REMINDER` (task, time, date), `TASK` (task, action), `STUDY`
  (subject), `KNOWLEDGE` (topic), `MOOD` (mood, polarity), `TIME` (city).

## Intents (19 classes, 12,557 utterances total)

| Intent | Count | Purpose |
|---|---:|---|
| GREETING | 534 | Openers: hi/hello/hey/namaste variants |
| GOODBYE | 750 | Closers: bye/see you/goodnight |
| THANKS | 750 | Gratitude expressions |
| HELP | 750 | "What can you do" / how-to-use queries |
| ABOUT_TARA | 750 | Identity/capability questions about the bot |
| SMALL_TALK | 750 | Casual chit-chat, "how are you" |
| TIME | 540 | Current-time queries (incl. per-city) |
| DATE | 650 | Current-date/day-of-week queries |
| WEATHER | 643 | Weather/forecast queries with city + date slots |
| REMINDER | 750 | "Remind me to X at Y" with task/time/date slots |
| TASK | 750 | Add/complete/list/delete to-do items |
| GENERAL_QUERY | 578 | Trivia facts, unit conversions |
| KNOWLEDGE | 600 | "Explain X" educational/definition queries |
| STUDY | 600 | Study help, exam prep, quiz requests (CS/engineering subjects) |
| JOKE | 570 | Requests for jokes/humor |
| AFFIRMATION | 650 | Yes/agree/confirm variants |
| NEGATION | 650 | No/disagree/cancel variants |
| MOOD | 560 | Emotional-state disclosures (positive/negative/neutral) |
| UNKNOWN | 732 | Gibberish + out-of-scope requests (fallback/OOD class) |

Every intent has natural paraphrase variation (prefixes like "hey tara, ",
"quick question - ", punctuation/politeness suffix variants, casual
misspellings) so semantically similar inputs map to a single intent label —
e.g. `hello`, `hi`, `hey`, `hello tara`, `hi there` all → `GREETING`.

Responses are **intent-level**, not utterance-unique: several utterances in
the same intent share a response drawn from a small pool of valid replies
for that intent (this mirrors how a real slot-filling/intent-routed
dialogue manager works, and keeps the response set consistent rather than
overfit to exact phrasing).

## Conversation history & user memory

Intent/response pairs alone don't capture multi-turn context or
personalization, so two small companion samples are included to show how to
extend this into a full chatbot backend:

- `conversation_history_sample.jsonl` — example session logs: a `session_id`,
  ordered `turns` (each with `speaker`, `text`, `intent`, `timestamp`),
  showing how single-turn rows above compose into a conversation.
- `user_memory_sample.json` — example per-user preference/memory store
  (name, preferred name, recurring reminders, study subjects, mood log)
  that a memory-augmented dialogue manager could read/write.

These are illustrative scaffolding, not bulk-generated at the 10k+ scale —
plug your own session/user logic around the intent dataset above.

## Suggested use

1. **Intent classifier**: fine-tune a transformer encoder (e.g. DistilBERT)
   on `utterance → intent` using `tara_train.jsonl`, validate on
   `tara_val.jsonl`, evaluate on `tara_test.jsonl`. `label2id.json` gives you
   the class index mapping.
2. **Slot filling**: use the `entities` field as weak supervision for a
   simple slot extractor (span match on `utterance`) for `REMINDER`,
   `WEATHER`, `TASK`, `STUDY`, `KNOWLEDGE`, `MOOD`.
3. **Response selection**: once intent is predicted, sample/rank among that
   intent's response pool (or fine-tune a seq2seq head on
   `utterance → response`).
4. **Deployment size**: ~12.5k rows / ~2-3 MB as JSON — light enough to bundle
   directly in a Streamlit app or serve from a small SQLite/JSON file on
   Vercel without a separate database.

## Regenerating / extending

`generate.py` is deterministic (seeded) but fully editable — add more base
phrases, slot values, or templates per intent and rerun to grow any intent
up to `TARGET_MAX` (currently 750) with automatic de-duplication.
